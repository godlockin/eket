# 00 — 序言：为什么写这个系列

> **目标读者：** 听过"EKET"、想判断它值不值得花 2 小时的人。
> **读完能拿到：** 一套可工作的心智模型，以及把你带来的问题导向正确入口的指针。

## 为什么写

EKET 仓库已生长超过一年。如今它涵盖：

- 约 6,400 行架构文档
- 5 个 Rust crate（core、cli、server、engine、context-mon）
- 11 个 Node.js 模块族
- 100+ bash 脚本
- 3 份 ADR
- 完整 SDK（JavaScript + Python）
- 一个 Web dashboard
- 一套多 evaluator 基准

这是相当大的表面积。新读者——无论是工程师、经理还是研究员——面对同样的问题：**从哪里开始，相信什么？**

这个系列就是答案。它不是文档（文档归文档）。它是**评注**——解释**为什么**代码长这样、**哪些**取舍关键、**应该**带走什么。

## 一份文档服务两个读者

每篇文章采用同样的形状：

| 章节 | 读者 | 时间 |
|---|---|---|
| TL;DR + 核心要点 | 任何人 | 30 秒 |
| Executive Summary | 决策者 | 1 分钟 |
| 动机 + 核心论点 | 任何人 | 5 分钟 |
| 协议如何运转 | 工程师 | 10–20 分钟 |
| 取舍与替代方案 | 架构师 | 5 分钟 |
| 实现要点 | 工程师 | 5 分钟 |
| 经验教训 | 任何人 | 3 分钟 |
| 参考 | 任何人 | 没空就跳过 |

Executive Summary 永远在文章最前。其它都不读，也请读它。

## 怎么用这个系列

- **评估用：** 读 01、02、15。你会知道 EKET 适不适合你的技术栈。
- **采用用：** 读 00、01、10、12。你会知道怎么安装和上手。
- **贡献用：** 读 01、03、06、09。你会知道哪些设计决定已定、哪些还开放。
- **研究用：** 读 01、04、06、07、13、15。你会拿到完整的概念图。

## 约定

- 所有文件引用形如 `path/to/file.ext:line`，在 GitHub 上可点击。
- `assets/diagrams/` 中的图被多篇文章共享；引入图的章节会写在文件名里。
- 同一术语在两篇文章出现时，链回 `GLOSSARY.md`。
- 框架变化时系列更新。看 `INDEX.md` 里每篇的 `Last verified` 字段可知某条断言的新旧。

框架本身是 EKET 社区的成果。系列是某个人对那项工作的提炼——必然片面、偶尔出错、永远欢迎指正。如果本系列的某条断言与源码不一致，**信源码**。系列是地图，不是版图。
